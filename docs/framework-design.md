# Lumen Engram 记忆库框架

> 遗忘≠删除，就像人脑一样，只是权重变低了不是没有了。

---

## 一、核心理念

记忆不是被抹去，而是权重降低、激活概率下降。重复提及会重新强化。模拟人脑的遗忘曲线与突触可塑性。

---

## 二、四层记忆分类

| 层级 | 存什么 | 类比 |
|------|--------|------|
| **工作记忆 Working Memory** | 当前对话、目标、临时状态 | 短时动态组装，不直接固化为长期记忆；有价值的内容会被重新提取进入长期层 |
| **情景记忆 Episodic Memory** | 具体事件：时间、人物、上下文、原话依据 | 日记本，带时间戳 |
| **语义记忆 Semantic Memory** | 多次经历巩固出的稳定事实、偏好、关系、结论 | 知识图谱 |
| **程序/技能记忆 Procedural Memory** | 怎么操作工具、完成项目、执行固定流程 | 能力库 |

**关键路径：** 情景记忆 →（多次重复 / 情绪强化）→ 语义记忆。这是"经历变知识"的巩固过程。

---

## 三、核心组件

### 1. Cognitive Router（认知路由器）

- 像前额叶，根据当前话题、目标、人物、情绪、任务**组合调用**对应层级的记忆
- 不只是关键词匹配，是上下文感知的智能分发
- 最早确定的核心模块，但尚未成熟；与巩固逻辑并列为最难实现的部分

### 2. 情绪与价值权重

不是单一 importance 标签，是多维评分：

- 情绪强度
- 重复次数
- 最近激活时间
- 对长期目标的影响
- 对关系或人物的重要性
- 当前任务相关性

情绪强、价值高的记得牢，模拟人脑情感记忆优先。

### 3. 遗忘与强化机制

- 普通闲聊 → 权重自然衰减（艾宾浩斯曲线式）
- 反复提及 / 情绪强烈 / 影响长期决策 → 权重强化（突触可塑性）
- 遗忘 = 可检索概率降低，原始记录仍在，可被重新唤醒

### 4. 主动回忆（Active Recall）

- 不等用户搜索，因当前状态、任务、人物或相似情境**主动联想**旧事
- 状态相似也能触发，不只靠关键词命中

---

## 四、写入机制

```
对话发生 → 实时判断是否值得记 → 写入情景记忆
                ↓ 值得记
          带时间戳 + 人物 + 情绪 + 原话进入情景底座（Chroma 负责向量化索引与相似检索）
                ↓
        周期性巩固：多次出现的情景 → 抽象为语义记忆
```

---

## 五、检索流程

```
用户输入 → Router 分析当前上下文
    ↓
判断需要哪类记忆（工作 / 情景 / 语义 / 程序）
    ↓
组合调用，按权重排序
    ↓
返回结果（动态组装当前所需工作记忆）
```

---

## 六、冲突修正

- **来源隔离：** 不同来源的记忆分开存
- **三态标记：** 确认 / 待核对 / 失效
- **保留旧依据：** 新记忆覆盖旧记忆时，旧的还留着不删
- **版本控制：** 可追溯

---

## 七、线程恢复

- 每次对话动态组装"当前所需工作记忆"
- 不是手动选摘要、不是重建文件
- 系统自动判断该带哪些上下文

---

## 八、与竞品方案对比

| 维度 | Lumen Engram | 传统档案型方案 |
|------|-------------|---------------|
| 核心目标 | 连续认知、关系演变、主动联想 | 侧重保存完整记录、搜索旧记录、重建上下文 |
| 原始记录 | 情景底座 + Chroma 向量化索引 | 日志流式存储，实时写入 |
| 记忆分类 | 四层（工作/情景/语义/程序） | 通常扁平化，原始聊天 + 关键词标签 |
| 写入机制 | 实时判断是否值得记 + 周期性巩固 | 侧重被动全量存储 |
| 语义巩固 | 多段经历逐渐形成稳定结论 | 生成摘要，通常无情景→语义升华路径 |
| 检索机制 | Router 组合调用（目标/人物/情绪/任务） | 侧重关键词匹配 / 模糊多轮检索 |
| 主动联想 | 有，状态相似可唤醒旧记忆 | 通常无，靠用户主动搜索 |
| 情绪系统 | 情绪强度和价值改变记忆权重 | 通常只有 importance，无情绪维度 |
| 遗忘机制 | 降低激活概率，重复提及重新强化 | 通常无遗忘，无限膨胀 |
| 冲突修正 | 来源隔离、三态标记、保留旧依据 | 通常无版本纠错机制 |
| 线程恢复 | 动态组装当前所需工作记忆 | 手动选择摘要 / 重建文件 |
| 可审计性 | 需额外设计 | 通常较强：原始记录 + 时间索引完整 |
| 可视化 | 待设计 | 通常较强：时间轴、摘要、重要度 |
| 落地难度 | 高（Router 和巩固逻辑最难） | 中等（大部分功能可直接实现） |

---

## 九、技术栈（建议实现）

- **向量数据库：** Chroma（情景底座的向量化索引与相似检索）
- **全文搜索：** FTS / trigram 索引（候选方案，非架构绑定）
- **Agent 架构：** Router 作为中央调度器
- **记忆生命周期：** 写入 → 加权 → 检索 → 强化/遗忘 → 冲突消解
