# Lumen Engram

**给长期对话型 AI 用的长期记忆系统。** 记得住，也记得清是谁说的、在哪说的、现在还算不算数。

中文名：长明。

---

## 它解决什么问题

一个 AI 陪同一个人聊几个月，会遇到三类典型故障：

1. **记错人**：AI 自己复述过的话，被当成用户说的，越传越像真的（回声共识）。
2. **记旧事**：用户早就改了主意，系统还拿三个月前的说法当现状。
3. **乱翻旧账**：用户随口一句撒娇或寒暄，系统也去库里搜一圈，塞进一堆不相关的记忆。

Lumen Engram 的设计目标，就是让这三件事在结构上难以发生，而不是靠提示词祈祷模型自觉。

## 核心特点

- **每条记忆都能追回原话。** 证据层只追加、不改不删，每条记录绑定原始文件、行号和内容哈希；召回时可以按出处回查，对不上原文的一律降级为「待核」。
- **分清是谁说的。** 每条证据记录说话人。AI 自己的转述、其他 AI 的话、用户转发的内容，都不会被记到用户名下；转述在召回时降权并标注来源。
- **新事顶旧事，但不删历史。** 新事实与旧事实冲突时，经两遍模型判断（便宜档初判、强档复核）后给旧事实打「可能已过时」的软标记，排序靠后；原记录一字不动，可随时撤回。
- **该不该查，先判再查。** 召回前先由路由判断这句话需不需要翻记忆、查什么、查多深；寒暄、撒娇、纯计算题直接跳过。命中的候选再经模型精排，低于阈值的不注入。
- **混合召回。** 关键词（FTS5 三字/二字双索引）+ 向量（bge-m3）候选，用倒数排名融合（RRF）合并；向量服务不可用时自动退回关键词。
- **密钥打码。** 入库前、送模型前、注入对话前都过一道脱敏，覆盖常见 API key、GitHub token、Bark 推送地址等，没有关闭开关。
- **可视化与人工校对。** 可把全部事实导出为 Obsidian 仓库，在手机或电脑上浏览，勾选即可把错误记忆收起，同步回服务器生效。

## 架构

```
会话记录（jsonl）
    │
    ├─ 采集：原话原样入证据层（evidence，只追加）
    │        每条带 source_path + 行号 + sha256 + 说话人
    │
    ├─ 蒸馏：会话安静后按切片抽取「一件事」，必须带逐字引文
    │        （可选）值得记闸：过滤流水、转述、临时状态，实验中，默认关
    │
    └─ 事实层（facts）：语义字段不可改写，只能作废
             valid_from / valid_to / supersedes 串成时间线
             stances：认 / 不认 / 悬置，只追加，改主意留痕

召回链路：
  用户消息 → 钩子预筛 → 路由（查不查、查什么、查多深）
           → 混合召回（FTS + 向量，RRF） → LLM 精排（≥7 分才注入）
           → 以「线索，非结论」的形式注入对话（最多 2 条）
```

## 防回声共识

用户说一次某件事，AI 复述一次，另一个 AI 再复述一次。如果三条都算独立支撑，系统就会把 AI 的回声当成「用户反复确认过的事实」，召回几次之后越来越像真的。

Lumen Engram 在**入库、召回、归纳**三个口子分别设防，全部在代码里检查，不靠提示词。

**入库（硬规矩，没有开关）**

- 每条证据记录说话人；认不出说话人的消息计数后跳过，**绝不默认算成用户**。用户转发的他人内容按转发识别，不记到用户名下。
- 证据是谁说的，从它产出的事实主体就只能是谁：AI 说的话产不出「用户喜欢……」。
- 「我们」类事实（涉及双方）必须在支持证据里同时有双方各自的原话，只有一方说过的，要么落回那一方，要么丢弃。
- 事实里的数字必须出现在原话里。
- 规则在抽取校验和写库两处都检查，任何写入路径都绕不过；历史上标错说话人的证据不改原行，在修正层（`evidence_actor_fix`）里改判。

**召回（降权、标注、不强化）**

- 一条关于某人的记忆，如果挂的证据里没有一条是这个人本人说的，就判为「只有转述」：
  - 排序权重乘以 1/3；
  - 注入对话时标注〔转述·来自某某〕，让模型不把它当成本人的话；
  - 被召回也不增加热度，避免转述被想起几次就越排越前。
- 用户确认过、钉住的记忆豁免。

**助手自记（`engram_remember`）**

助手主动写记忆，本质上是又一条「AI 的话进库」的通道，所以单独收紧：

- 写进去的记忆主体永远是助手自己，状态是待核；没有任何参数能把它改成用户的事实，也不能直接设为已确认或钉住。
- 证据标记为助手说的二手证据，不参与归纳计票，不会给用户事实提供支撑。
- 带数字或日期必须附原话，数字要出自原话；重复和高度相近的内容拒绝。
- 默认每个会话最多 3 条、每天最多 5 条，可用 `ENGRAM_REMEMBER_PER_SESSION` / `ENGRAM_REMEMBER_PER_DAY` 调整。用户纠正另走纠正层，单独计数。

**归纳（夜间聚类，把多条相近记忆抽象成一条）**

- 一个簇要够格：≥3 条成员，其中**用户本人原话 ≥2 条**，且来自 **≥2 个不同日子**；AI 和第三方的话不进归纳提示词。
- 簇里有矛盾（同一属性两个值、一肯定一否定、标过「可能过时」）→ 不写。
- 说了「经常」「总是」，但引用的原话撑不起频率 → 拒绝。
- 归纳里的数字必须出现在被引用的原话里。
- 产出写成新的派生记忆，标「归纳」，用 `derived_from` 连回原话；**原记录一行不改**。

宁可一条不归纳，也不让系统靠自己的复述给自己盖章。

## 快速开始

依赖：Python 3.10+、PyYAML；向量检索和夜间归纳另需 numpy。

```sh
git clone https://github.com/bear40828-cmyk/Lumen-Engram.git
cd Lumen-Engram

python3 -m venv --system-site-packages .venv
.venv/bin/pip install pyyaml numpy

cp .env.example .env                 # 模型接口与开关，见下文「模型与费用」
cp persona.env.example persona.env   # 部署相关的称呼、说话人标签、路径（不进仓库）

export ENGRAM_HOME=$PWD ENGRAM_ENV_FILE=$PWD/.env
python3 recall.py --stats            # 首次运行自动建库建表
python3 recall.py --auto "上次去海边是哪年的事"
```

不配置模型接口也能运行：抽取与精排会退回规则与关键词路径。

## 模型与费用

哪些环节要调模型，各用什么档：

| 环节 | 配置项 | 什么时候调 | 建议档位 |
|---|---|---|---|
| 召回精排 | `RERANK_MODEL` | 每轮对话（路由判定需要查时） | 便宜档 |
| 切片蒸馏 | `EXTRACT_MODEL` | 会话安静后，约每 30 分钟 | 强档 |
| 新事顶旧事初判 | `EXTRACT_MODEL` | 蒸馏出新事实时 | 强档 |
| 新事顶旧事复核 | `TIMELINE_CONFIRM_MODEL` | 初判认为要顶替时 | 强档 |
| 夜间聚类归纳 | `CLUSTER_MODEL` | 每天一次，有调用上限 | 强档 |
| 向量嵌入 | `CF_API_TOKEN` / `CF_ACCOUNT_ID` | 新事实入库后补齐 | Cloudflare 免费额度通常够用 |

不需要模型的：采集入库、证据核对、关键词召回、防回声检查、助手自记、导出 Obsidian。

所有用途共用一把 key，按用途单独指定模型，没单独配的退回 `DIGEST_MODEL`。配了 `FALLBACK_*` 后，主路由限流或欠费时自动切到备用。每次调用的 token 用量记在库里的 `llm_usage` 表，可按天查账。

参考：作者日常使用（日聊天量中等，以 DeepSeek V4 为主），全部模型费用约每天几毛到一元人民币。

## 推荐配置

开关默认全关，是为了让每项能力都能单独开、单独回滚，出问题时能定位到具体哪一层。
日常使用推荐在 `.env` 里打开这一组：

```ini
ENGRAM_RAW_ONLY=1
ENGRAM_DISTILL_SLICE=1
ENGRAM_TIMELINE=1
ENGRAM_INVALIDATE_CHAIN=1
ENGRAM_TIMELINE_CONFIRM=1
ENGRAM_METAMEM=1
ENGRAM_CONTEXT_ROUTE=1
ENGRAM_SELF_REMEMBER=1
ENGRAM_CLUSTER_SUMMARY=1
```

即：原话入证据、切片蒸馏、新事顶旧事并复核、召回时查冲突、按场合路由、助手自记、夜间归纳。

## 功能开关

所有开关登记在 `flags.py`，读取顺序：环境变量 `ENGRAM_<名字>` → `.env` → 默认值。

**常用**

| 开关 | 作用 |
|---|---|
| `DISTILL_SLICE` | 会话安静后切片蒸馏 |
| `RAW_ONLY` | 原话只入证据、不直接晋升（与 `DISTILL_SLICE` 配合） |
| `TIMELINE` + `INVALIDATE_CHAIN` | 新事顶旧事（判断 + 写软标记，需同时开） |
| `TIMELINE_CONFIRM` | 用强档模型复核取代判断 |
| `METAMEM` | 召回时检查证据冲突 |
| `CONTEXT_ROUTE` | 按对话场合调整召回策略 |
| `SELF_REMEMBER` | 开放助手自记工具 |
| `HANDOFF_INJECT` | 开窗注入交接摘要 |
| `CLUSTER_SUMMARY` | 夜间聚类归纳 |

**实验中**：`VALUE_GATE` / `VALUE_GATE_UNION`（值得记闸）、`ATOMIC_SPLIT`（旧事实拆原子）、`UNIFIED_GATE`（一次调用完成晋升与分类）、`RERANK_FLASH`（精排降档）。

**回滚与对照**：`LAYERED_RETRIEVE`（旧版分层召回）、`CONSOLIDATE`（旧版规则巩固）。

## 已知边界

- 分类（偏好 / 稳定事实 / 规矩 / 事件）是规则判的，长对话文本上会有误判；类型只影响衰减快慢和排序，不影响记录是否存在。
- 早期版本整条消息直接入库的旧事实还没全部拆成原子事实，可用 `ATOMIC_SPLIT` 按批处理，可整批撤回。
- 新事顶旧事的精度依赖复核模型；只开初判、不开复核时误判偏多，不建议单开。
- 召回评测与纠正层依赖使用者自己的对话数据，开箱不能直接跑出个人数据上的结果。
- `tests/test_known_defects.py` 把历次审查发现的问题固定为回归用例，其中 5 个标为跳过并写明原因（涉及要重建整张表的迁移，或已被新路径取代的旧逻辑）。
